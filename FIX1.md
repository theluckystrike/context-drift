# Fix round 1: Context Drift 0.1.1

The independent review of 0.1.0 scored it 5/100 with 24 findings. Every finding is fixed in 0.1.1, and three are only partly fixed (CDR-12, CDR-13, CDR-14; see below). Measured results are in `NOTES.md`. In short:
- **Tests:** 189/189 pass (`node --test`).
- **Review cases:** 48/48 of the reviewer's adversarial cases pass (0.1.0: 23).
- **Real source repos from the review:** 4 true findings and 0 false (0.1.0: 4 true, 14 false).
- **Corpus:** about 9 % of findings are false.
- **Speed:** every ReDoS input from the review runs in under 15 ms (0.1.0: over 20 s).

| CDR-01 | P0 | `globToRegExp` is gone. Repo-controlled globs from inline code, `.mdc` `globs:`/`applyTo:`, `.gitignore`, `.git/info/exclude` and Taskfile wildcard tasks go through `compileGlob`/`globMatch` instead. That matcher works segment by segment: a two-pointer wildcard match per segment, and a DP over (pattern segment, path segment) for `**`, so there is no exponential backtracking. Caps: 512 characters per glob, 64 segments, 32 brace expansions, 200 globs per file, and a work budget per file (past it, a glob counts as matching and is not reported). The extension runs the engine in a worker thread (`src/worker.js`) with a 30 s budget; the worker is restarted on timeout. Test: `test/redos.test.js`, about 1 MB per adversarial input, each under 50 ms of CPU time. The reviewer's `redos.js`: glob `*a`×40 takes 11 ms, `**/`×100 5 ms, `.gitignore` 11 ms, `.mdc` 4 ms. |
| CDR-02 | P1 | Every line regex rewritten so no two adjacent quantifiers can match the same characters: `MIN_SUFFIX`, the Node/Python/Go version patterns (`version(?=\s)`, and `\s*` inside each optional group), and the link regex (`[` is excluded from the label). Makefile rules (`splitMakeRule`), justfile recipes, Taskfile keys (`parseTaskKey`) and TOML keys (`splitTomlKey`, `stripTomlTrailingComment`) are parsed with linear scans. Code spans are found with a backtick-run index (binary search), with no rescans. Lines over 4,000 characters are skipped and reported; files over 1 MB are skipped and reported; at most 20,000 code spans and links per file. The reviewer's 1 MB inputs now take 5–14 ms. |
| CDR-03 | P1 | Saves trigger a check only for instruction files (cache reused) and manifests (`package.json`, Makefiles, justfile, Taskfile, `pyproject.toml`, lockfiles, `.nvmrc`, `.gitignore`, `.gitmodules`, …; manifests re-read, file list kept). Created or deleted files re-walk the folder (debounced; `node_modules`, `.git` etc. ignored). The context is cached per folder in the worker, with invalidation levels `none` < `manifests` < `files`. git runs only through `runGit`: `spawn` with a promise, a 3 s timer that resolves even if git is stuck, a process-group kill, `--no-optional-locks`, `core.fsmonitor=false` and `log.showSignature=false`. The synchronous `analyzeWorkspace` never runs git; `analyzeWorkspaceAsync` does. Also fixed:
- The `executeCommand('workbench.actions.view.problems')` promise is now caught.
